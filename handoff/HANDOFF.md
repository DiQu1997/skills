## 第一部分 · 这个项目是什么

### 1.1 一句话

**AI 写代码，画布是人保持指挥权的地方。**

Code Canvas 把"读代码/读 diff"从一维线性文档变成二维空间画布：真实代码
卡片 + 类型化连线 + 分层注释 + 故事线镜头，由 agent 策展生成，人用眼睛
的并行感知能力一眼读结构，只在需要文字的地方读文字。

### 1.2 产品定位（最重要的一节，作者最新的表述）

用 code agent（Claude Code / Codex）写代码的根本代价：**人对代码的认知
退化成"agent 的转述"**。代码文件读着太累，没人再读，作者对自己仓库的
了解和控制在无声流失。Code Canvas 的终局定位是把控制权还给作者，覆盖
三个时刻：

1. **平时** → 仓库的活画布（living map）：不靠读文件保持对代码的了解
2. **动手前** → **计划画布**（尚未实现，路线图第一优先级之一）：agent
   要改代码时先产出计划画布——哪些现有卡会被动、哪些是幽灵卡（将新建
   的函数，虚线框）、计划加删哪些线、每步为什么。作者在画布上审批计划，
   而不是读一段计划文字
3. **动手后** → diff 画布（已实现）：复盘实际改动。关键设计：**计划和
   diff 用同一张底图**——"它说要动三张卡，实际动了四张，多出来的是什么"
   一眼可见。计划 vs 实际的可对照性就是控制感的来源

作者原话（保留，因为它是需求的源头）：
> "本质上所有人都失去了对 code 的认知、了解。我希望这个表现方式可以用来
> 作为辅助……当 agent 决定修改代码时也通过这个可视化来表达变化的计划，
> 以及 diff review，这就可以极大提高用 code agent 写代码时作者对代码
> 保持控制的能力。"

### 1.3 项目起源（为什么推倒重来）

作者原有两个 skill（code-review-narrative / code-reading-walkthrough，
仍在 DiQu1997/skills 仓库里，视为前身、不再演进）产出线性 HTML 长文档。
诊断：那是"一本更好的书"——storyline→step→大段 prose，阅读仍是从上往下
滚动，文字越多单位信息成本越高。方向性问题，打磨解决不了。

起点洞察（作者第一条消息）：**人眼一眼看到的是 2D 范围；视觉对空间结构
的感知是并行的，读文字是串行的**。位置、颜色、连线、包含关系不用"读"，
一眼获得。读 code/diff 从上往下从左往右是低效且艰难的。

## 第二部分 · 设计体系（每条含理由，很多含反例）

### 2.1 方向反转（对 no-code 的批判性继承）

Blueprint / Node-RED 这类 node-and-wire 图：写起来低效（图作为源码，
输入密度太低），读起来高效。所以反转：**代码是源码，图是投影（view）**。
no-code 死于用低密度媒介写；我们用高带宽媒介读。

从 Blueprint 偷的四样：带类型的端口、两种线严格分开（执行线 vs 数据线）、
collapse/expand、comment box（→故事线着色区域）。
坚决不偷的一样：**表达式级粒度**（一个加法一个节点 = 噪音炸弹）。

### 2.2 信息通道分配

| 信息类型 | 通道 |
|---|---|
| 拓扑（谁调用谁、数据流向、模块边界） | 空间布局 + 连线 |
| 变更 delta | 颜色（diff 着色） |
| 意图 / 不变量 / tradeoff | 短注释，贴在具体代码行边 |
| 代码本身 | 原文保留，永远可见可展开 |

**代码必须是原文**：信任建立在"我看到了真实的行"上。唯一放宽（评测后
裁决）：允许对超宽行做保持 token 顺序的换行重排（注释续行补 //），须披露。

### 2.3 粒度

节点 = 函数级代码卡片。函数内部 → 文本通道（缩进就是图，不画线）；
函数之间 → 图通道（调用与数据流，文本最弱连线最强之处）。

**长函数的块大纲**：15 行以上或深嵌套的函数在卡内做逻辑块分段——
连续行段打包成块（色条 + 名字 + 一句话功能 + 行号范围），嵌套结构套
children，默认折叠成大纲，逐层点开。块是**行段树不是语法树**——按
"一句话说得清功能"分段，不按 AST。判断标准：每个 for/if 都成块 =
Blueprint 噪音；水位检查/全表扫描/收割 = 正确粒度。

### 2.4 两种线 + 策展原则

- 调用/执行线（灰白）：call site 行 → 被调卡。便宜可靠，骨架，默认画
- 数据流线（琥珀，带值名 label）："介于主菜和配菜之间"（作者原话）——
  只画故事需要的值旅程。评测中最好的例子：nano-vllm 里 key 和 resp 两根
  琥珀线在 store 汇合；codex 里 SandboxErr::Denied 是全图唯一的回头路

**线是策展的不是全量的**。静态分析全量边 = 毛线球（Sourcetrail/CodeSee
的死法）。完备性由代码本身保证，图只画"此刻你需要看见的关系"。

### 2.5 注释四层体系

1. 故事线 blurb（区域标签下一句话，≤20 字）：这块区域管什么
2. 块 explain（块条「说明」按钮展开，≤120 字）：为什么这么写/坑在哪。
   块折叠时也能开——"大纲 + 理由"零代码阅读模式
3. 行级 note（琥珀卡片 + 引线锚行，≤60 字）：这行的意图/不变量。
   **note 是断言不是猜测**，不确定的不写
4. 变元注释 terms（虚线下划线标识符，点击行下展开，≤60 字）：这个变量
   装的是什么。vLLM 类代码难读一半在计数变量上

背景（bg flavor，青色）与意图（intent，琥珀）分味：青 = 读懂它需要的
领域知识；琥珀 = 这段代码自己的道理。背景三层：画布级卡（corner nw，
总览点亮，≤80 字）、故事线 blurb、概念级 note。
**字数上限是闸门：写不进上限说明还没想清楚，不是上限太小。**

### 2.6 故事线（storyline）

- 空间形态：画布着色区域（成员卡 bbox 自动包裹）
- 叙事形态：steps = 镜头路径 + 逐步点亮（本步的线实色、行高亮、note
  点亮，其余淡出）；步进点按故事线着色，标题带色签，点区域标签跳章
- 叙事顺序主权高于分章：一条故事线可分几段出现
- step 排序按**读者的问题**（怎么进/怎么出/坏了会怎样），不按文件序

### 2.7 个性化（不同人看同一码想看不同的东西）

两层：生成时 `meta.audience`（这张图为谁写，所有 prose 按它定深度语言
风格）；运行时读者画像（页面右上角自由文本，存 localStorage）——注入
块问答提示词 + 每条 explain/term 出现「按我的画像重讲」（经 serve.py
桥现场改写，徽标 + 可还原 + 按 (画像,元素) 缓存）。
**立场：默认解释永远保留，个性化是叠加视图不是覆盖**——事实锚点只有
一份，画像只改讲法（改写提示词里写死"保持事实与代码依据不变"）。

### 2.8 规模闸门（大仓库策略）

估计"这张图要讲的东西"的行数（非仓库总行数）：
- ≤ ~2000 行 → 细粒度画布（函数级卡 + 完整故事线）
- 更大 / "讲讲这个仓库" → **领航图**：卡片 = 子系统（≤9 张），卡内
  "名片代码"（入口函数/核心类型的原文连续摘选 ≤12 行），线 = 每种关系
  一根代表线，故事线 = 架构关切（2-3 条），末步列 3-5 个深潜主题邀请
  用户挑，挑了再出细粒度深潜画布（一主题一张）
理由：注意力预算（细图容量 ~10 卡）、读者问题序列（先"分几块"后"为什么
这行"）、生成质量（摊大了解释必空洞）。

### 2.9 Diff 画布（第三种画布类型）

card.diff = { added:[行号], removed:[{after, code}] }。added 绿条；
removed 红删除线展示原文，不占行号不参与锚点；卡头 +n/−m 徽标；图例
自动补色样。故事线 = 变更意图（最小形态"本次变更"+"未改动的邻居"）。
step 序 = 评审者问题序列：**治什么病 → 核心改动 → 连锁影响 → 风险。
风险步必选——没有风险判断的 diff 画布只是上色的 diff。**
removed 只放读懂变更必需的原文。示例：demo/cache-diff.json。

### 2.10 交互与问答

- 块级问答：每根块条「问」按钮 → 侧抽屉。serve.py（桥 claude -p /
  codex exec，/__alive 探测）在线模式；无服务降级为复制完整上下文提问
  到剪贴板。历史 localStorage + sidecar
- 布局哲学：agent 只给粗位置 {col, band}，渲染器精排（测行宽定列宽、
  同列冲突每次重绘动态下推、区域实时包裹、focus bbox 自动算镜头）。
  **不要给像素坐标**

### 渲染器的关键机制（不读代码也要知道的）

- **锚点级联**：线/引线锚到行 → 行被折叠退到所在块的大纲条 → 卡折叠退
  到卡边缘。visibleProxy() 实现
- **动态下推**：卡片展开/折叠随时改变高度，每次 drawWires 重排同列 y、
  重摆 note、重包区域、重设世界尺寸
- **note 跟随**：above 位被挤压先下滑，无空间退化为挂目标左侧
- **指针捕获教训（重要工程债规避）**：pointerdown 立即 setPointerCapture
  会把 click 重定向到视口，吞掉一切点击。现行方案：位移 >4px 才捕获——
  静止是点击，移动是拖拽。**以后加任何可点元素都不用再进豁免名单**
- 双指捏合缩放（移动端）、touch-action:none
- fitAll 无缩放下限裁切（放开到 0.1；两个评测考生都撞过 0.3 下限的墙）
- 调试尾缀：#s2 直达步骤；x 全展开 / e 开说明 / t 开变元注释 / q 开问答

### 已知债务

- note 车道解决压卡，但线仍从 note 背后穿过（dim 下可读，不完美）
- 语义缩放缺中间层（远景卡片应只显示签名，现在是缩小的全文）
- 同卡多条 above 位 note 原地重叠（文档警告了，未修）
- 步骤状态累积不重置（#s5 直达 ≠ 顺序走到 5；自检以顺序走为准）

## 第四部分 · 质量体系与评测（项目的护城河）

### 4.1 质量地板（机器强制）

validate.py ERROR 清零 → 渲染 → 截图自检清单（SKILL.md 六条：无压盖、
focus 框住 caption 提到的东西、线两端可见、大纲可读、每卡至少被一步聚焦、
caption 说"注意 X"则 X 在画面且点亮）→ Playwright 测试防交互回归。

### 4.2 零上下文考试（回答"新会话能不能稳定产出这种质量"）

方法论三原则（eval/README.md）：考生零上下文（只有 skill 文件 + 仓库 +
一句用户话，方法论必须完全由 skill 文件承载）；考题固定（**不许为过题
往 prompt 加提示——那是把答案写进考卷**）；机器打分为地板人审为天花板。

打分硬指标：validate 无 ERROR、**卡片代码对源仓库 token 流可溯源 ≥90%**
（容忍披露过的换行重排：去空白 + 删 //）、结构预算、截图存在。

### 4.3 基线（2026-08-16，openai/codex，本包 examples/ 有完整产物）

| 考卷 | 结果 | 溯源 | 用时 |
|---|---|---|---|
| codex-nav 领航 | PASS | 9/9 逐字 | 22 min |
| codex-exec 深潜 | PASS | 15/15 token 流 | 34 min |

两位考生的自检循环都真实工作（各修 4-5 个布局问题）；他们的"SKILL 哪里
没写清"反馈已全部吸收进 SKILL.md（行宽裁决、宽度预算 ≤5 列、note 摆位
规则等）。**考生报告全文在 examples/*/examinee-report.md——它们的决策
叙述本身就是高质量示范。**

尚未跑基线的考题：nanovllm-deep、requests-nav（`python3 eval/run.py
exam <id>`，每张 20-40 分钟）。

## 第五部分 · 作者与协作方式（对下一个 session 很重要）

- **语言**：中文交流。产物（画布文字、文档）也是中文优先
- **节奏**：作者先抛方向性想法 → agent 给结构化分析和有立场的建议
  （给推荐，别罗列选项）→ 作者说"可以/开始做" → agent 全程自主执行到底
  （做完自检、测试、提交、推送、给成品链接），中途不问琐碎问题
- **评审文化**：作者重视诚实——测试结果如实报、评测不粉饰、agent 产物
  要独立核验（那次逐字溯源核查 9/9、15/15 是信任的来源）。发现自己踩了
  自己写的失败模式要明说
- **移动端场景真实存在**：作者常在手机上看结果。交付方式：Artifact
  发布（可交互）+ 关键截图（秒开）双轨
- **基础设施**：作者有云盒子，tailscale 组网 + claude CLI 已登录。
  这是"个人 hub service"路线的前提（见路线图），不用担心部署
- **宁滥勿缺**是作者对信息传递的明确要求——本文件即按此写成

## 第六部分 · 路线图（当前共识的优先级）

作者已确认的方向判断：不做 SaaS（信任墙 + LLM 账单 + 多租户，收益/成本
不成立）；"app"的正确形态是 IDE 扩展而非独立应用；但**个人 hub** 因云
盒子的存在而成立。

1. **canvas hub（下一件事，约一天）**：serve.py 升级为常驻多画布服务——
   画布库列表页、生成请求接口（本机 claude 跑）、活问答。跑在作者云盒子
   上 → tailscale 全设备可用，**手机上问答/重讲也活**（此前 Artifact 无
   LLM 运行时能力，已验证：目前只有 downloads 和 mcp 两种 capability）
2. **计划画布（产品灵魂，1-2 天）**：schema 加 mode:"plan" + 幽灵卡
   （将新建的函数，虚线）+ 变更意图标记；skill 加"改码前先出计划图"
   规程；通过 Claude Code hooks 挂载（ExitPlanMode 前产计划画布，作者
   批了才动手；Stop hook 后自动出 diff 画布对照）
3. **结构提取器（大件，"日用"的地基）**：tree-sitter/LSP 机械提取
   结构层（卡=函数、call 线、diff 映射、粗布局），**不含 LLM，毫秒级**。
   叙事层（故事线/note/explain）由 agent 异步增量补。这是"代替 IDE
   文件审阅"的前提——没人为每次 review 等 20 分钟
4. IDE 扩展：结构层实时 + 叙事层异步 + 点卡跳真实文件（杀手交互）
5. GitHub App（有团队拉力再做）：PR 自动出 diff 卷贴链接；复用同一个
   提取器 + 异步叙事层
6. 小件待办：问答沉淀（好答案写回 canvas JSON）、多画布索引（画布的
   画布）、语义缩放中间层、评测集扩容跑基线
