# Code Canvas — 设计纪要 v0

> 推倒重来的新方向。取代 code-review-skill / code-reading-walkthrough 的
> "线性 HTML 长文档" 形态。本文档记录已收敛的设计决定和待定问题。

## 0. 产品定位（agent 时代的代码控制面板）

用 code agent（Claude Code / Codex）写代码的根本代价：**人对代码的认知
退化成"agent 的转述"**。代码文件读着太累，没人再读，作者对自己仓库的
了解和控制在无声流失。Code Canvas 的定位是把控制权还给作者——在三个时刻：

1. **平时**：仓库的活画布（living map）——不靠读文件保持对代码的了解
2. **动手前**：agent 提出修改计划时，用**计划画布**表达"我要动哪些卡、
   加哪些线、为什么"——作者在画布上审批计划，而不是读一段计划文字
3. **动手后**：diff 画布对照计划复盘实际改动（计划 vs 实际用同一张底图）

一句话：**AI 写代码，画布是人保持指挥权的地方。**

## 1. 问题诊断

旧项目本质上是"一本更好的书"：storyline → step → 大段 prose 字段，最终
仍是从上往下滚动的线性文档。文字量越大，单位信息的阅读成本越高。
方向性问题，打磨解决不了。

核心洞察：**视觉对空间结构的感知是并行的，读文字是串行的**。
位置、颜色、连线、包含关系不用"读"，一眼获得。

## 2. 方向反转（对 no-code 工具的批判性继承）

Blueprint / Node-RED 这类 node-and-wire 图：**写起来低效（图作为源码，
输入密度太低），读起来高效**。所以反转方向：

- no-code：图是源码，代码是生成物 → 失败
- 我们：**代码是源码，图是投影（view）** → 写读不对称，各取所长

## 3. 信息通道分配

| 信息类型 | 通道 |
|---|---|
| 拓扑（谁调用谁、数据流向、模块边界） | 空间布局 + 连线 |
| 变更 delta | 颜色（diff 着色） |
| 意图 / 不变量 / tradeoff | 短注释，贴在具体代码行边上 |
| 代码本身 | 原文保留，永远可见可展开 |

## 4. 粒度（与 no-code 的关键分歧）

- 节点 = **函数级代码卡片**，卡片内部是真实的、语法高亮的代码原文
- **函数内部 → 文本通道**：局部控制流（if/for/嵌套）代码本身表达最好，不画线
- **函数之间 → 图通道**：跨函数调用与数据流，文本最弱、连线最强

绝不做 Blueprint 的表达式级粒度（一个加法一个节点 = 噪音炸弹）。

**长函数的块大纲**（v1.2 增补）：函数内部不画线，但长 / 深嵌套的函数在
卡片内部做**逻辑块分段**——连续行段打包成块，块有专属颜色、名字和一句话
功能描述；嵌套结构（深层 for / if）在块内继续套子块。默认折叠成大纲
（只见色条），逐层点开。行的归属用左侧色条 + 底色表达，嵌套块的色条
并排缩进，层级一眼可见。块是**行段树**，不是语法树——按逻辑功能分段，
不按 AST 节点分段。

## 5. 两种线，严格分开（继承自 Blueprint）

- **调用/执行线**（灰白）：call site 那一行 → 被调函数卡片。便宜、可靠、默认画。
- **数据流线**（琥珀）：值从产生处流向消费处。贵（需真正理解代码），
  **介于主菜和配菜之间**：不全画，由 agent 在故事需要时选择性画几根关键的。

绝不把调用/依赖/数据流画成同一种箭头。

## 6. 分层细节（tiered detail）

- **重点函数**：展开态，有**行级端口**——连线精确锚到具体行；
  端口同时兼任 **note 的锚点**（行级短注释用引线贴在行边）
- **次要函数**：折叠成签名块
- **一切块都能点开看真码**：没有任何节点是"只有描述没有代码"的

## 7. 线是策展的，不是全量的

静态分析全量边 = 毛线球（Sourcetrail / CodeSee 的死法）。
线由 agent 作为叙事的一部分挑选。完备性由代码本身保证（它永远是真的），
图只负责"此刻你需要看见的关系"。

## 8. Storyline 的新形态

保留旧项目的叙事策展（这是死掉的可视化工具们缺的东西），但改变载体：

- storyline = 画布上一块**着色区域**（Blueprint comment box 的用法）
- step = **镜头路径 + 逐步点亮**：镜头移到当前卡片，本步相关的线实色，
  其余淡出；相关行高亮，相关 note 点亮
- 读者随时可以缩出去看全图（色块 = 章节地图），也可以顺故事一步步走

## 9. 背景层（配菜）

背景文字是配菜：少量、贴位置、随镜头淡入淡出。三个层级：

- **画布级**：一张紧凑的背景卡（"这是什么系统 / 这次变更为什么存在"，≤4 句），
  放在画布入口处，总览时点亮，走进故事线后淡出——背景属于远景。
- **故事线级**：region 标签下的一句话 blurb，回答"这块区域在管什么"。
- **概念级**：背景 note（青色），与行注释 note（琥珀）区分 flavor：
  琥珀 = 这段代码的意图 / 不变量；青色 = 读懂它需要的领域知识
  （术语、协议、历史包袱）。同样锚定到具体卡片 / 行，在相关 step 点亮。

约束：每处背景有字数硬上限（画布级 ≤80 字，blurb ≤20 字，概念 note ≤60 字）。
写不进上限说明还没想清楚，不是上限太小。

## 10. 语义缩放四层

1. 最远：storyline 色块 + 模块框 + 画布级背景
2. 中间：卡片只显示函数签名 + 端口
3. 展开卡片：长函数先呈现**块大纲**（色条 + 名字 + 一句话）
4. 贴近：块逐层展开 → 完整代码原文 + 行注释

- **A 领航卷**：规模闸门起效（102 crate → 9 卡领航图 + 深潜菜单），
  validate 0/0，9/9 卡代码逐字可溯源，关键架构断言抽查属实
- **B 深潜卷**（exec/沙箱全流程）：15 卡 4 故事线 11 步，validate 0/0，
  15/15 卡 token 流可溯源（换行重排已披露），去程/回程的空间叙事成立
- 两者的自检循环都真实工作（各自发现并修掉 4-5 个布局问题）
- 共同撞墙：fitAll 0.3 缩放下限裁总览（已修）；两份 "SKILL 没写清楚"
  清单已并入 SKILL.md（行宽裁决、宽度预算、note 摆位规则、状态累积等）

结论：skill 在零上下文新会话中可产出接近手作质量的画布，
质量地板由 validate + 自检清单托底。

## 现状

- **生成管线已落地**（v0.1）：`schema.md`（JSON 格式）→ `render.py` +
  `template/canvas.html`（数据驱动渲染器，含测量布局 / 锚点级联 /
  focus 镜头计算）→ 自包含 HTML。skill 定义见 `SKILL.md`
- 布局折中方案已实现：agent 给 `{col, band}` 粗位置，渲染器测行宽定列宽、
  同列冲突下推、region 实时包住成员、镜头由 focus bbox 自动计算
- `demo/cache-demo.json` / `.html` — 生成管线的参考示例（与手工 mock 同内容）
- `demo/nano-vllm.json` / `.html` — 第一个真实仓库案例（GeeeekExplorer/nano-vllm，
  6 步故事线）。真实代码带来的渲染器修正：卡片宽度上限放宽到 800px（真实行
  常见 90+ 字符）、steps 支持 `unfold` 指定块、同列冲突下推改为每次重绘动态
  执行（展开的卡会撞到下方卡）、above 位 note 右移避开区域标签
- `mock/canvas-mock-v1.html` — 手工排版的形态原型，历史参考，勿再改
